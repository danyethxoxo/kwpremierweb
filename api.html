API de Propiedades de KW Premier

Para conectar el inventario de Command con el sitio de KW Premier.

En corto: nos mandas las propiedades con un POST a /properties, en JSON, con tu llave en el header x-api-key. Nosotros nos encargamos del resto. Si ya integraste otros portales, esto funciona igual.

Qué es esto

Esta API recibe el inventario de propiedades para publicarlo en el sitio de KW Premier. Está pensada para que la consuma quien administra Command en KW México, del mismo modo en que ya se envía inventario a otros portales inmobiliarios.

No hace falta darse de alta en ningún programa de desarrolladores ni pasar por aprobaciones: basta con una llave de API que nosotros te entregamos.

URL base

https://iloetojomzqtadkithtv.supabase.co/functions/v1/api-propiedades

Pasos para conectar

Pídenos tu llave de API

Te entregamos una llave con el formato kwp_live_… por un canal seguro. Se muestra una sola vez; guárdala donde guardes el resto de tus credenciales.

Verifica que funciona

Una llamada a GET /me debe responder con el nombre de tu integración.

Manda tu primer lote de prueba

Un POST /properties con 2 o 3 propiedades. La respuesta te dice exactamente cuáles se guardaron y, si alguna fue rechazada, por qué.

Programa el envío completo

Manda el inventario cada vez que cambie, o de forma periódica (cada hora o cada día, lo que te acomode). Reenviar una propiedad que ya existe la actualiza, no la duplica, así que puedes reenviar todo sin problema.

Autenticación

Todas las llamadas llevan tu llave en el header x-api-key:

# Ejemplo
curl 'https://iloetojomzqtadkithtv.supabase.co/functions/v1/api-propiedades/me' \
  -H 'x-api-key: kwp_live_TU_LLAVE_AQUI'
Sobre la llave No la publiques en código de cliente ni en repositorios. Si se filtra, avísanos: la revocamos y te generamos otra al momento, sin afectar lo ya publicado.

Endpoints

GET /me
Verifica que la llave sea válida y devuelve a quién pertenece.
{
  "nombre": "KW México - Integración Command",
  "permisos": ["propiedades:escribir", "propiedades:leer"],
  "activa": true
}
GET /property_types
Devuelve los valores aceptados en tipo, operacion y estatus.
POST /properties
Manda propiedades. Crea las nuevas y actualiza las que ya existen, usando tu id como referencia. Hasta 500 por llamada.

Si alguna propiedad viene mal, las demás sí se guardan y en errores te decimos cuál falló y por qué: 

{
  "ok": false,
  "recibidas": 3,

  "rechazadas": 1,

    { "indice": 1, "id": "KW-1002",
      "error": "\"operacion\" debe ser uno de: venta, renta. Recibido: alquiler" }

}
También aceptamos nombres en inglés Si tu sistema ya exporta con otros nombres, entendemos title, price, bedrooms, bathrooms, address, images, property_type, status, agent_email, entre otros. No hace falta que traduzcas nada.
GET /properties
Lista lo que tenemos guardado. Útil para verificar que llegó completo.
ParámetroDescripción
pagePágina. Por defecto 1.
limitCuántas por página. Por defecto 20, máximo 200.
estatusFiltra por estatus. Acepta varios separados por coma.
operacionventa o renta.
updated_afterSolo las modificadas después de esa fecha (ISO 8601).
GET /properties/:id
Detalle de una propiedad. El :id es el mismo que nos mandaste al crearla.
DELETE /properties/:id
Da de baja una propiedad del sitio. No se borra: queda como suspendida, para no romper enlaces que ya se hayan compartido. También puedes lograr lo mismo mandándola por POST con "estatus": "suspendida".

Dudas frecuentes

¿Qué pasa si mando la misma propiedad dos veces?

Se actualiza, no se duplica. Usamos tu id como referencia, así que puedes reenviar el inventario completo las veces que quieras.

¿Tengo que mandar solo lo que cambió?

No hace falta. Puedes mandar todo cada vez. Si prefieres mandar solo lo modificado, también funciona.

¿Cómo quito una propiedad?

Mándala con "estatus": "vendida", "rentada" o "suspendida", o usa DELETE /properties/:id. Deja de mostrarse en el sitio de inmediato.

¿Puedo mandar el inventario de varias oficinas?

Sí. Usa el campo market_center en cada propiedad para indicar de cuál es.

¿Aceptan XML en lugar de JSON?

Sí. Si ya tienes un feed en XML armado para otros portales, podemos recibirlo tal cual sin que tengas que construir nada nuevo - dinos y te pasamos el endpoint para eso.

¿Hay ambiente de pruebas?

No hace falta uno aparte: manda propiedades con "estatus": "no_publicada" y podrás verificar que llegaron con GET /properties sin que se publiquen en el sitio.
